# 历史订单批量删除

在历史订单标题栏、“刷新”左侧点击“批量管理”，用复选框或点击订单主体选择，再点击“删除所选（N）”。选择操作在标题下方展开，没有操作、进度或结果时不占空白区域。管理模式不打开订单、不消除新结果红点，隐藏单项删除和识别重试；退出后恢复。选择只保留在当前页面，退出管理清空，不存入浏览器。

“全选当前列表”只选择已加载、可见的订单，每次最多100条，不代表账号在服务器上的全部历史订单。状态刷新保留按订单ID保存的选择，新订单不自动勾选；刷新后离开当前列表的订单移出选择范围。若正在跟踪的任务令本页超过100条，全选取前100条，其余可分批处理。

删除前只确认一次，列出订单名称、数量和排队或识别中的数量。确认后冻结目标，等待当前保存队列；保存失败不发出任何删除请求，草稿及选择保留。单项删除也执行相同保存检查。执行期间不允许更改选择、重复提交、切换订单、修改参数或服务地址，识别与进度轮询继续运行。关闭或刷新仍在执行的页面会触发浏览器离开提示。

前端逐项调用现有 `DELETE /api/reviews/{job_id}`，沿用服务端权限和取消机制，不新增接口或数据库字段。某项失败不会回滚已成功项。完成结果分别显示已删除、取消处理中、失败、结果待核对和未处理数量；接口报告文件清理未完成时单独提示。识别中订单收到取消回执后移出列表，但清理由worker继续完成，不表示当时已经彻底删除。独立SW文件目录不在本功能的清理范围内。

失败项保留选择，可点击“重试失败项”，重新确认后仅重试失败项，不包含网络结果未知项。网络中断、30秒请求超时、无法读取或无效回执都标为“结果待核对”，不自动重发删除请求；点击“刷新核对”，仍能在列表中找到的订单可再次选择并确认删除。列表未显示不代表服务器文件已经清理完成。认证或权限错误停止后续删除，剩余项保留选择，待恢复登录或权限后重新处理。

全部成功后自动退出管理，保留可清除的结果摘要；存在失败、待核对或未处理项时继续保留管理模式。成功删除当前打开订单才清空审图界面，删除其他订单不会清空当前内容。红点、上传关联、轮询和已删除ID保护由单项与批量共用，旧响应不会恢复订单；服务地址或登录用户变化后不再继续旧批次或把旧回执应用到新会话。

验证命令：`node scripts/test_history_bulk_deletion.mjs`、`node scripts/test_history_bulk_deletion_browser.mjs`、`.venv/Scripts/python.exe scripts/test_review_deletion_api.py`，并回归历史状态、红点、批量上传、保存和确认。浏览器使用模拟API，后端删除测试使用临时数据库及临时文件，不删除真实订单或调用云端识别。

当前前端目录已挂载。更新前端文件及JS/CSS缓存版本后，按Ctrl+F5强制刷新即可，无需重建或重启Docker。
