# 多页识别与订单切换性能

## 使用方式

多页PDF仍按页独立审图，默认同时识别2页。原始文件和拆分后的单页PDF不压缩、不改写。某页识别完成即可打开，其余页继续处理。

再次打开最近的订单时，先显示本页缓存，并在原图上方提示“正在核对最新版本”。此时可以浏览、缩放和旋转；修改、确认、打印、导出和生图需等核对完成。失败时保留只读内容，可点“重试加载”。切换前保存失败会留在原订单，避免丢失草稿。

缓存仅保留最近3个已保存订单，图片另受128MiB解码像素预算限制，超限释放较早的图片。缓存不写入浏览器本地存储，刷新、退出登录、切换用户或服务地址后失效；未保存草稿不进入缓存。历史列表和页面核对清单共用进度轮询，任务全部结束后停止轮询。

## 图片和证据

- 整页预览PNG、初始整页OCR和Qwen输入最长边不超过3000像素；小图片不放大。
- Qwen使用独立RGB JPEG（质量90），内部上限8MiB，超限等比缩小。不是对供应商API大小限制的声明。
- 小字、粗糙度和载荷等仍可从原PDF渲染局部高清证据，每页每次最多12个局部输入，旋转版本计入预算。
- 页面缓存由原文件SHA、页码、方向、区域及处理版本区分。整页预览、OCR和定位复用已有渲染；RapidOCR每进程复用一个实例，推理加锁。
- 标注的原图逻辑尺寸与实际预览像素分开保存。旧锚点、人工位置和原图标识通过兼容映射保留，缩小图片不改变参数或人工标注。

## 读取与后台核验

普通审图、标注、图片权限读取不执行OCR、图形解析或旧数据恢复。旧记录需要升级时，在现有任务队列登记隐藏的本地核验任务，由worker执行，不调用Qwen、不生成识别红点。新识别任务优先于本地核验任务。

任务按订单、审图修订及核验版本去重。后台结果只有在原审图修订未变、worker租约有效且未取消时才能提交；标注另外合并最新人工位置。人工值、主动清空和已确认值仍采用原有保护。后台失败保留原因，不在普通读取时反复执行。

`GET /api/reviews/{id}?metadata_only=true`只返回`job_id`、`review_revision`、`annotation_revision`、`source_document_id`、`preview_version`、`verification_state`。可以登记后台任务，但不在请求中执行核验。版本相同后解锁缓存，版本不同则取得完整结果后解锁。

完整响应可带`loading_metadata`和`preview_pages`；页面可带`preview_width`、`preview_height`、`scale_x`、`scale_y`、`image_version`等。`width/height`继续表示原图逻辑坐标尺寸，旧客户端可忽略新增字段。审图内可选`local_verification`仅用于服务器记录核验版本，不进入SW。

已保存修订的生图就绪检查可缓存；创建生图任务时仍先检查保存成功，并执行最终服务端校验。历史冻结包及原参数重试不变。无需数据库迁移。

## 排查与验收

渲染、Qwen、OCR、本地核验及接口日志分别记录耗时。Qwen拒绝时保存`qwen_error_diagnostics.json`，包括HTTP状态、错误码、简短原因及图片尺寸、字节数，不记录认证信息或图片编码。普通400不重复提交；保留原有明确格式兼容重试和网络重试。

- `scripts/test_review_performance.py`：六页原附件尺寸、JPEG体积、跨DPI渲染复用、局部证据、OCR实例/锁、诊断脱敏、轻量读取、后台任务及并发保护。
- `scripts/test_review_switch_browser.mjs`：缓存立即显示、只读锁、版本变化/失败、晚到响应、连续21次切换以及缓存和像素上限。
- 另回归PDF分页、多规格、人工标注旋转拖动、参数保存和SW输出。

本地离线目标是已存订单读取P95低于1秒、缓存内容呈现低于300毫秒。模拟接口的切换耗时不能代表云端识别速度；Qwen准确率和实际耗时通过上线后的正常上传验收。测试不新增云端调用或生产SW任务。

## 本次离线实测

2026-11-05，用户六页扫描PDF完整重放，未调用云端或生产SW：

- Windows本地完整已存订单20次读取P95约16毫秒；模拟接口连续21次切换，多轮实测最慢约50～75毫秒。页面保持单一查看器，缓存和像素预算通过检查。
- Docker内Poppler首次渲染六页约44.36秒，随后不同OCR DPI入口复用同页缓存约0.02秒；六页预览合计26.92MiB，JPEG最大单页约0.96MiB。
- 多规格、原PDF载荷高度链、粗糙度、页码4～6、人工位置、保存失败及晚到响应回归通过。

这些数字只说明本地环节和模拟切换性能，不代表Qwen的请求耗时或真实识别准确率。

## 部署

```bash
docker compose build api worker
docker compose up -d worker
docker compose up -d api
```

检查健康后Ctrl+F5刷新。旧记录首次打开可能触发一次后台本地核验，之后复用结果。
