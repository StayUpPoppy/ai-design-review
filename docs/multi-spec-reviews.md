# 多规格图纸识别与独立审图

图片/PDF仍通过原“压缩弹簧”入口上传。单规格保留原流程；多规格来源打开工作台内的“规格核对”，清单只读、初始不勾选。独立参数区块和规格表行分别保留，即使几何参数相同也不合并。每文件最多50种，超过页数配置、不完整或无法确定划分时显示识别问题，不静默丢项。

勾选后点击“创建所选规格的审图记录”，每种规格分别进入现有编辑、确认和SW生图流程。创建不会自动确认、生图或打开子记录。未选规格与已创建关系保存在服务器，可刷新或稍后补建；勾选状态不保存。历史来源行可展开已创建规格，子记录按原顺序排列。来源识别完成只产生一次新结果提示，建单不产生重复提示。

## 识别与工程边界

沿用一次文件级Qwen视觉请求，增加`document_mode=multi`、`layout`、`complete`、`spec_count`、`common`和`variants`。`common.applies_to_all=true`才继承公共参数和技术要求；规格内值优先，冲突保留问题和原始响应。候选稳定ID由服务端生成，刷新或建单不重新识别。

候选包含`variant_id/order/code/page/region/parameters/load_points/technical_requirements/source_context/reference_values/issues`。区域为显示方向归一化矩形；位置不明允许为空，此时不跨规格自动定位气泡。图号只从整图识别字段保存，不从规格代号或文件名猜测。子记录初名为“图纸名称 · 规格代号”，无代号用“规格N”，之后可独立编辑。

表头决定字段角色，表格尺寸不进入旧的“按数字大小猜外径”逻辑。明确mm压缩变形量可由`H=H0-deflection`转换工作高度并保存计算来源；缺单位保留待核对。极限工况不当压并载荷，压力分级不当精度等级。刚度、应力等表内计算结果保留为参考，系统公式照常计算。图二的D1若不能明确其内/外/中径含义，保留数值与公差供人工核对，不借代号猜测。

## 数据与接口

迁移`20261025_01`在`drawing_reviews`增加`record_kind(single/source/variant)`、可空`parent_review_id`、可空`variant_id`、来源索引及父来源+规格ID唯一约束。旧记录默认single，不重写旧参数、确认或冻结SW任务。来源保存整图及完整识别结果，仅能查看、拆单和删除；子记录分别拥有修订、草稿、确认、审计及生图版本。权限使用原ERP所有者规则。

- `GET /api/reviews?limit=100&root_only=true`：最多100个顶层入口。默认不带`root_only`兼容旧客户端。
- `GET /api/reviews/{source_id}/variants`：来源修订、候选、问题、原图页面及现存子记录。
- `POST /api/reviews/{source_id}/variants/create-reviews`：事务建单：

  ```json
  {"variant_ids":["variant_abc"],"expected_source_revision":1,"idempotency_key":"operation-uuid"}
  ```

锁定来源后全批提交或回滚。已有规格返回原ID；同键原选择重试返回原回执，同键不同选择返回409。原回执中的子记录已删除时标记`deleted`，不重建；补建须新的操作键和最新来源修订。

原文件、预览页通过硬链接共用内容，OCR缓存和文档标识共用来源；每个子记录拥有自己的候选快照及标注文件。自动气泡仅使用本规格及明确公共区域。首次读取子记录会本地准备这些文件，不调用模型，也不覆盖已编辑草稿。

删除子记录仅清理该记录及其目录链接；原图仍由来源保留。删除来源组须携带`expected_source_revision`，一次确认删除来源及全部子记录；来源在确认后发生变化返回409重新核对。父子重复选择只发送一次来源删除，最多100条实际审图记录。识别中沿用取消机制；文件清理失败提示待处理，不能宣称彻底清理。

## 部署与离线验收

本次有数据库迁移，服务器更新代码后依序执行：

```bash
docker compose build api worker
docker compose run --rm api alembic upgrade head
docker compose up -d api worker
```

检查`/api/health`和数据库，浏览器Ctrl+F5。仅重启旧镜像无法启用新识别逻辑。

离线测试：`scripts/test_multi_spec.py`、`scripts/test_multi_spec_pipeline.py`、`scripts/test_multi_spec_browser.mjs`。两张本地附件配合手工转录的模拟Qwen响应，验证3块和13行，不代表重新进行了云端识别。PG迁移及事务锁测试使用`test_multi_spec_postgres.py`创建、销毁独立临时测试库，不操作服务库中的真实订单。桌面/手机截图位于忽略目录`outputs/multi-spec-qa/`。

## 视觉请求超时与多规格兜底保护

文件级视觉识别使用独立`QWEN_VISION_TIMEOUT_SECONDS`，默认至少360秒（旧通用超时若更长则保留更长值），显式设置可覆盖。连接上限为20秒；普通单图成功返回时立即继续，不等待该上限。文字翻译、AI对话和现有网络重试策略不变。多规格输出只列实际字段和必要依据，避免逐行复制空模板造成过长响应。

Qwen超时、异常或未提供多规格结构时，复用现有OCR/PDF结果检查强多规格迹象：规格表中多行独立复合尺寸，或多个参数区块重复完整几何表头。它只用于阻止错误混合，不能据此猜参数或创建规格。检测命中后，保存候选、失败原因及`multi_spec_diagnostics.json`，任务标为失败，提供原订单重试，不再将单规格OCR拼接结果标成完成；普通单规格OCR兜底保留。不新增自动Qwen或OCR调用。

模型声明有多种规格却未返回完整集合，以及返回因长度被截断时，同样报告失败，保存实际响应供追溯。已有被旧兜底标成完成的历史记录不会自动改写，需重新上传；无完整模型响应时不能凭空恢复候选。

`python scripts/test_multi_spec_timeout.py`覆盖实际保存的13行OCR回放（存在`outputs/multi-spec-timeout-qa/ocr_snapshot.json`时使用）、超时失败状态、无混合审图记录、人工重试成功、普通单图兼容、重复OCR、多页及截断响应。全部使用临时数据库和模拟模型返回。

## 来源原图读取

来源记录的只读限制仅约束工程编辑、标准化和生图，不应阻止所有者读取原图。产物下载接口显式允许来源记录的授权读取，继续校验订单归属及文件目录边界；不撤销参数确认、不改变审图修订，不重跑识别。历史来源也适用，更新API后刷新规格核对页即可显示原图。

回归测试直接读取清单中返回的真实PNG地址，核对状态、图片字节及读取前后的审图快照；同时验证跨用户访问、目录越界、缺失文件，以及读取后的来源编辑/生图限制。

## 公共参数气泡与区块定位

公共参数的数值可以继承，位置不能从其他规格借用。子记录优先在自己的区块查找重复标注；没有匹配时仅使用明确的公共说明区域。缺少可靠区块时不进行全页回退。区域必须包含完整数字框，跨区文字不会直接成为锚点；存在可靠PDF单词框时可在区内逐词匹配。

独立计算区块使用参数名称与同一行数值配对，支持“簧丝直径d、中径D、有效圈数n、总圈数n1、自由高度H0、压并高度”等明确名称。纵向规格表使用当前规格行及对应列头；无法确定D1角色或仅有同值数字时保留待定位。重复OCR字框合并，多个不同位置仍匹配时不自动选点。公式值、项目参考及无原图依据的人工值不新增自动标注。

若PDF/OCR明确读到本规格代号，但其位置不在模型给出的规格区域内，则报告“规格区域与原图代号位置不一致”，暂停该规格的自动定位。定位v2通过同页唯一规格代号、实际横线或相邻已核实代号重建有效行，不按数组顺序或固定比例猜区域；模型原始区域及人工位置仍保留。

新子记录的`multi_spec_origin`附带字段来源、布局及规格区域集合；旧记录在定位时从已关联来源读取同样的只读上下文，不改参数、确认或审图修订。标注文档增加可选`multi_spec_location`（策略版本与区域指纹），旧多规格自动位置在首次读取时升级，普通单规格不因此重建。人工位置及来源不明的历史位置继续保留，重新补定位可纠正过时的自动位置。

本地OCR的原始文字和已完成裁剪继续复用；补定位处理记录按规格区域与策略区分，避免一个规格的“已处理”阻止另一个规格补定位。每页最多12个局部输入，不增加Qwen请求。

离线回归：`python scripts/test_multi_spec_annotations.py`，覆盖3区块、13行、公共区域回退、页码、同值歧义、跨区OCR、缓存预算、旧记录升级、人工并发修改及审图修订不变。本地存在`outputs/multi-spec-annotation-qa/saved.json`时还回放已保存的三规格响应/OCR；原附件可用时输出无历史锚点的新建标注供`node scripts/test_drawing_annotations_browser.mjs --multi`验收。旋转回归继续使用`node scripts/test_drawing_rotation_browser.mjs`。

后续热卷与规格行核实升级详见[热卷精度反推说明](hot-coiled-accuracy.md)。该升级包含可选修正草稿元数据与前端缓存更新，无数据库迁移。更新后执行`docker compose up -d --build api worker`，检查健康，再Ctrl+F5打开已有规格即可按新策略更新标注，无需重新上传。

## 布局名称兼容与缓存恢复

公共解析器使用`multi-spec-layout/v1`：布局字段去首尾空白、忽略大小写，`rows`和`blocks`保持原义，`columns`兼容为`blocks`。未知名称继续明确报错；文档类型、完整性、数量上限、页码及结构约束不放宽。仅有多列的普通载荷表不会因此成为多规格。参数可由common继承，每个独立区块仍分别保留自己的工况。原始Qwen响应不修改；来源的可选`layout_normalization`记录原名称、统一名称及规则版本。提示词给出合法rows/blocks示例，不再使用无效枚举占位。

已保存完整响应的布局兼容失败可点击原“重试”。`POST /api/reviews/{job_id}/retry`仍返回202并沿用队列。在失败任务行锁内，服务端校验本订单目录、完整响应及原文件，向已有`options.multi_spec_layout_replay`记录原文件/响应SHA256、相对路径、原失败原因和版本。worker再核对指纹后本地解析，复用正常来源保存流程，不请求Qwen、其他云端识别或自动创建子记录。缓存入队后损坏或变化时本次恢复失败，不自动回退调用模型。入队前缓存缺失/无效则沿用原有显式重试流程。

恢复保留订单ID、所有者、原文件和原响应，原失败诊断保留在`multi_spec_diagnostics.json`；恢复依据单独保存在`multi_spec_recovery.json`及审计中。重复投递发现既有来源时复用数据库快照和稳定规格ID，不覆盖子记录或重新创建。内部恢复选项不进入公开状态响应和SW。取消、权限及任务租约保护保持现状；部署不会自动重跑失败任务。

离线回归`python scripts/test_multi_spec_layout_replay.py`使用临时数据库和模拟模型，若存在忽略目录`outputs/multi-spec-layout-qa/saved-responses.json`，同时回放当前两份columns失败响应及以前blocks成功响应，并用已有OCR验证三个区块的气泡。覆盖新上传、手动重试的零模型调用、继承公共参数、不同工况、已有子记录、指纹变化、损坏缓存、取消和所有者隔离。

本次仅后端及说明变更，无需数据库迁移或前端脚本缓存升级。测试通过后执行`docker compose up -d --build api worker`，检查服务健康；Ctrl+F5后点击失败订单的“重试”，有效缓存可恢复为3种规格，无需重新上传。
