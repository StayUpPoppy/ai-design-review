# SolidWorks 命令格式

新建任务的 SW 请求与 `solidworks_preview` 使用相同模型投影。内部 `spring_generation_parameters/v2` 继续保留结构化材料、载荷点和原图技术要求；`solidworks_preview` 提供最终 SW 专用文本。

## 生图入口

“待处理”第三步为“生成图纸”，按钮“去生图”仅切换到“生图参数包”页签并聚焦该页签，不下载JSON、不创建任务。尚未就绪时同样可进入查看缺失、待确认及风险项。

“生图参数包”页不再提供“导出参数包”按钮；版式和姓名下方只保留“生成图纸”主按钮，桌面靠右，窄面板占满一行。仅服务器审图记录且生图服务可用、参数达到原有就绪条件时允许生成；本地导入数据继续可在AI对话中请求导出JSON，不能直接创建任务。AI对话导出及现有内部导出函数、接口继续保留。

导出从等待保存起占用当前操作状态，成功、请求失败及保存失败均在结束时按最新就绪条件恢复按钮和设置控件。状态卡片及按钮局部更新，不重建参数输入、切换页签或重置滚动。导出归属包含订单、用户、服务地址、导航轮次及独立操作标识；切换订单会失效旧归属，迟到结果不能下载错误订单、修改新页面或解除更新操作的禁用。保存失败时不读取参数包或创建生图任务。

离线验收：`test_review_workbench_ui.mjs`、`test_generation_package_ui.mjs`、`test_generation_package_chat_ui.mjs`、`test_generation_settings_browser.mjs`；覆盖入口导航、各就绪状态、保存/网络失败、慢导出、切换订单与新任务并发隔离。仅前端变更，更新JS/CSS缓存版本后Ctrl+F5生效，无需数据库迁移或Docker重启。

## 生图版式及姓名

“生图参数包”按钮上方提供图纸版式及生图人姓名。首次默认横版，姓名优先取 `/api/session` 的 `identity.real_name`，其次为 `username`；按订单恢复上次保存值。姓名主动清空后保持为空，保存草稿允许空值，导出及生图前要求非空且不超过256字符，只去除首尾空格。修改设置不撤销弹簧参数确认，也不改动登录身份或审计操作者。

审图JSON的可选 `generation_settings` 保存 `{"drawing_model":"X型","username":"阿拉伯特"}`。`X型`表示横版，`Y型`表示竖版。前端预览、手动和对话导出，以及新任务冻结参数包使用同一份设置；最终字段为模型对象同级的 `DrawingModel`、`Username`，不放入建模参数或标题栏。旧接口调用缺少设置时，服务端取横版及当前登录姓名；已有冻结包缺少字段时继续原样读取和重试。

任务列表显示冻结的版式和姓名，历史版本不会随输入框修改。“原参数重试”沿用冻结值；真实SW“重新生图”按当前已保存修订创建新TaskId。设置纳入参数哈希和幂等比较；保存失败不创建任务，晚到响应不得覆盖其他订单。无需数据库迁移。离线验证使用 `scripts/test_generation_settings.py` 和 `scripts/test_generation_settings_browser.mjs`，均不调用真实SW或云端模型。

## 对称公差与垂直度

新预览及SW `models[]` 在 `modelParameters` 后增加可选 `modelParametersTolerance`：仅接受“外径”“自由高度”“中径”，各自读取审图对应参数的上下偏差，不从内径或其他直径复制。参数必须明确已确认、名义值有效、依赖当前且无冲突或公差输入草稿；存在确认快照时须匹配当前数值及公差。

仅当上下偏差均有值、上偏差非负且上下等幅时输出绝对幅值，例如±1.5输出数字1.5。非对称和单边不近似为对称；缺值、未确认、失效、非法或不支持单位时独立省略。统一mm，不附加±、正负号、单位或字符串，不按名义尺寸的三位小数格式截断小公差。0保留；三项均不可输出时整个对象省略。原公差及页面文字不改写，不增加确认步骤或生图拦截。

标题栏“客户图号”后增加可选“垂直度A”，读取高级参数`perpendicularity`的已确认、当前有效、有限非负值并统一mm。0保留，图号缺失仍独立输出；无值、待确认、冲突、非法、失效或单位不支持时省略。原有“表面粗糙度”等字段名保持不变。

```json
{
  "modelParametersTolerance": {"外径": 1.5, "自由高度": 0.5, "中径": 0.2},
  "titleBlockProperties": {"材料": "50CrVA", "重量": 1.26, "客户图号": "YD4765145678", "垂直度A": 0.01, "表面粗糙度": 12.5}
}
```

前后端共用共享样例验证；新任务将新字段冻结到现有`solidworks_preview`和实际请求，纳入现有参数哈希。旧预览可缺少`modelParametersTolerance`和“垂直度A”，历史请求及原参数重试不重建、不补写。外部SW程序须按该契约支持绘制，本项目不修改外部程序。

页面右上角仅移除组织／厂名显示行，账号及“开发模拟”提示保留。`/api/session`组织信息、权限隔离和审计均保持原有用途。

本次有后端变更，无数据库迁移；回归通过后执行`docker compose up -d --build api worker`，检查健康并Ctrl+F5刷新。验证新任务JSON及模拟推送，不调用生产SW或云端识别。

## 技术要求前三项与材料过滤

2026-10-30起，新请求按已确认且当前有效的数据依次输出旋向、合并圈数及端部。例如（数值只是示例，不是默认值）：

```text
1.旋向：右。
2.总圈数：6.64，有效圈数：4.64。
3.两端并紧并磨平，磨面角≥270°。
```

旋向在技术要求中写左/右，`customProperties.旋向`继续传左旋/右旋。圈数保留实际小数，不按名义尺寸三位格式或载荷四位格式截断；不并紧时继续省略自动有效圈数。缺项、未确认或失效项不补默认值，合并行仅保留可输出部分，整项无内容则跳过，最终连续编号。磨面角只在并紧且磨平时添加，其余三个端部状态沿用现有文字。

自动材料行和结构化/旧文本回退中的独立纯材料条目不输出（材料/材质、中英文冒号均支持），标题栏材料正常传递。只识别完整的牌号/材料名称描述；含工艺、检验、附加条件的复合要求原样保留，不按关键词整句删除。

首部的独立同值旋向、圈数、端部句去重；旧默认端部句“两端并紧磨平，每端磨270°。”作为旧模板写法合并。不同数值、角度、范围及额外条件保留，复合句不拆删。其余要求保持相对顺序，F/P载荷点描述不变。只改变SW专用文本，不改审图正文、确认、标题栏字段或计算。

前后端共享`solidworks_technical_labels.json`和原有SW样例；新任务冻结新文本，历史冻结及原参数重试原样。同步更新JS缓存，无接口或数据库迁移；测试后执行`docker compose up -d --build api worker`，健康检查后Ctrl+F5刷新。

## 请求示例

总圈数、有效圈数支持有限正小数，例如 `"圈数": 10.5`、`"有效圈数n": 8.25`，人工输入的小数在参数包和模型请求中完整保留。图纸名称可在摘要编辑（最多512字符，允许清空），新任务冻结至 `source.drawing_name`，用于 `models[].modelName`；空值回退弹簧类型。历史冻结任务及原参数重试保留旧值。详见[圈数小数与名称编辑](decimal-coils-and-drawing-name.md)。

```json
{
  "TaskId": 1000000099,
  "models": [{
    "modelId": 1,
    "modelName": "订单2",
    "modelLabel": "压缩弹簧",
    "DrawingModel": "X型",
    "Username": "阿拉伯特",
    "materialCode": null,
    "modelParameters": {
      "线径": 1.8,
      "中径": 25.2,
      "自由高度": 19,
      "圈数": 4,
      "有效圈数n": 2,
      "是否磨平": 1,
      "是否并紧": 1
    },
    "modelParametersTolerance": {"外径": 1.5, "自由高度": 0.5, "中径": 0.2},
    "customProperties": {"旋向": "右旋"},
    "extraProperties": {
      "技术要求": "1.旋向：右。\n2.总圈数：4，有效圈数：2。\n3.两端并紧并磨平，磨面角≥270°。\n4.压并高度：Hb = 6.3 mm。\n5.当弹簧工作高度 H1 = 14.284 mm 时，对应工作载荷 F1 = 13.2 N。\n6.当弹簧工作高度 H2 = 12.284 mm 时，对应工作载荷 F2 = 18.9 N。",
      "P'": 2.9314,
      "C": 14,
      "τ_b": 451.2669
    },
    "titleBlockProperties": {
      "材料": "SUS304",
      "重量": 0.00642403,
      "客户图号": "YD4765020178",
      "表面粗糙度": 12.5
    }
  }]
}
```

技术要求的八类完整正文等价规则与前端分组、重复新增和补回遗漏一致，详见[技术要求去重说明](technical-requirements.md)。例如“硬度 HRC45-50”和“HRC45-50”仅输出一次，保留各自原始记录；不同标尺、试验载荷、部位、标准版本和附加条件不合并，未支持工艺采用严格文本比较。原写法用于展示，比较副本中的单位、次数和区间规范化不会改写用户正文。

SW专用文本将条目标签“绕制方向：”改为“旋向：”，`customProperties.旋向`仍只传“左旋”或“右旋”。条目开头的“其他要求：”及冒号被移除，兼容英文冒号和重复前缀；例如“其他要求：展开长度：约268mm。”输出为“展开长度：约268mm。”。正文中的普通用词不替换，其他类别标签、数值、条件和作用范围沿用原输出；清理后为空的条目跳过，最终连续编号。自动模板、结构化条目及旧文本回退均先清理输出标签再按现有规则去重。

此清理仅用于前端SW预览、手动／对话导出及服务端新任务，不修改审图正文、确认状态、内部`generation_parameters.technical_requirements_text`或通用分类规则。历史冻结`solidworks_preview`及`execution_options.solidworks_payload`继续原样读取和重试，不重新清理。共享样例`solidworks_technical_labels.json`覆盖中英文冒号、方向同义去重、工程条件、空条目、旧文本及历史冻结；运行`test_solidworks_export.py`、`test_solidworks_export_ui.mjs`、`test_solidworks_export_browser.mjs`和`test_solidworks_push_api.py`离线验证。无接口或数据库变更，部署执行`docker compose up -d --build api worker`，健康检查后Ctrl+F5刷新。

公司表面处理采用[49项版本目录](company-surface-mapping.md)辅助识别及编辑；下拉选择不另行拼接进SW。已确认的`content`是唯一成图文本，`standard_content`随正文同步，`surface_mapping`及原代号仅在审图和冻结包内追溯。新上传示例输出“表面处理：电镀-镀彩锌，镀层厚度≥15 μm，彩虹铬酸盐处理2级C型，并进行除氢处理。”；相同来源原代号不再经旧文本回退追加。名称冲突、转换未完成或空正文不输出；主动取消公司关联后仍可确认有效正文。不同工艺条件继续独立输出，历史冻结请求及原参数重试不变。

每条要求现只显示一个公司类型，复合工艺取第一项，完整工艺仍写在正文。已转换原文与OCR条目通过专用原文键、页码、范围及位置复核关联，可选`source_requirement_ids`由服务端重新验证；原代号仅作为来源保留，不独立计入确认或新任务结构化要求，也不经旧文本回退复活。关联投影不改写旧正文或确认，新增关联随下一次正常保存审计。不同条件、人工改写或位置冲突不自动隐藏，普通八类去重规则不变。

此例采用 SUS304、每端支承 1 圈、并紧磨平书页模型。Hb 已人工确认；没有图纸压并载荷 Fb，所以不把估算载荷写入技术要求。τ_b 仍使用有效估算结果。

- `P'` 使用 ASCII 单引号；三个计算键与“技术要求”并列，位于其后。值为 JSON 数字，四位小数，无单位字符串。合法零应力为 `0`，缺项、失效或不适用时省略对应键。
- 技术要求正文不重复标题，使用实际换行并连续编号。缺失条目跳过，其他已确认原图要求随后保留；模板句、结构化工艺要求及旧文本回退统一按完整条目去重，追加每条立即更新去重集合。不同原图位置的等价条目在新任务中只输出一次，原审图独立记录不删除；复合句及不同工程条件保留。
- 压并高度仅使用已确认、当前有效的输入或名义高度；上限参考不作为实际高度文字。唯一已确认的 Fb 与 Hb 高度一致时组合描述，不一致时分列并注明测试高度。没有 Fb 时只写 Hb。
- 工作点按原编号和顺序输出，保留百分比或绝对允差；支持 F3 等后续点。导出高度和力值转换为 mm、N，不支持的单位提示核对。
- `titleBlockProperties` 与 `extraProperties` 同级，按材料、重量、客户图号、垂直度A、表面粗糙度顺序输出。材料为已确认纯牌号，技术要求不重复独立材料句；重量为当前单件重量 Q，JSON 数字，单位 kg，最多八位小数；客户图号来自当前审图 `drawing_summary.drawing_no`，创建参数包时写入 `source.drawing_no` 并以字符串输出，仅去除首尾空白，保留前导零、字母、连字符及内部空白，不从文件名或任务编号补值；垂直度A为当前已确认、有效的非负mm数值，0有效；表面粗糙度为当前已确认、有效的 Ra 数字，单位固定 μm，不附单位文字。缺失键独立省略，重量缺失不影响客户图号，都缺失时发送空对象，不增加确认步骤或生图拦截。
- 粗糙度成功写入标题栏后，技术要求移除相同数值、单位、部位且无附加条件的独立粗糙度句，并连续编号。其它部位、不同数值、明确比较符以及复合工艺要求保留；不按关键词删除。原始参数、部位与识别证据继续保留。旧记录单位缺失沿用内部 μm 默认值，支持 µm、um 等价拼写，其它单位不直接当作 μm。
- 后端重新计算三个结果及重量，并在 `derived_parameters.solidworks_design_checks` 中冻结公式、输入、材料属性及版本。客户端缓存的 `design_checks` 不作为服务端依据。
- `solidworks_preview` 兼容旧 V2 记录缺少新增属性或客户图号；新任务冻结完整标题栏及图号快照，后续审图修改不影响该任务；历史任务的 `execution_options.solidworks_payload` 及幂等重试不改写、不补入客户图号。接口和数据库无需迁移，回调继续使用 `/api/solidworks/status`。

## 粗糙度缺值的可选参考

压缩弹簧的Ra确实缺失时，输入框下提供“采用 Ra 12.5／采用 Ra 6.3／不添加”三个快捷按钮，用户也可直接在输入框填写其他有效正数，不再单独提供“自定义”按钮。两个值均为两端面的项目参考，磨平、不磨平及端部状态未知时均可选择，不代表原图识别或统一标准规定。初次展示不修改参数、不默认确认、不写入SW；已有识别值、人工值、已核实候选、真实冲突或失效数据不显示参考按钮。只有未核实疑似且正式参数为空时，仍可选择项目参考。

点击参考按钮填入对应的12.5或6.3、μm及两端面，来源包含`human_roughness_reference`，必须通过现有单项或批量确认后才输出标题栏JSON数字。直接输入改值后显示“人工填写”，撤销参考来源及旧确认快照。采用同一历史数值也不恢复原确认，不伪造原图文字、位置或气泡，不在技术要求编辑列表增加记录。采用审计记录实际`reference_value`，保存失败保留本地修改并提供重试。

“不添加”保持空值，并通过参数元数据`roughness_reference_dismissed=true`记住选择；保存重开收起提示，可点击“查看常规参考”重新选择。旧记录缺少标记时沿用缺值提示，已有人工清空默认收起；人工清空后不自动补回。选择及确认使用现有保存、审计和失败重试机制，无新增接口、数据库迁移或生图拦截。空值、未采用、未确认、失效和非法值继续省略`titleBlockProperties.表面粗糙度`；历史冻结请求及幂等重试保持原样。

验收（2026-10-18）：30组粗糙度阶段／端部组合通过前后端投影、保存重开和冻结请求检查；原有119组SW投影、参数确认及保存竞态回归通过。实际浏览器覆盖单项／批量确认、不添加与重新展开、自定义、失败重试、连续修改和切换订单；本地旧订单缺值结果离线验收未修改原文件。桌面及390px截图位于忽略目录`outputs/roughness-reference-qa/`。本机api、worker重建后健康检查及部署网页回归通过，未发起新的云端识别或真实外部生图任务。

### 粗糙度候选及原始依据精简

参数行只显示简短来源或核对状态；原图候选按钮为“Ra 数值 μm · 部位”，未知部位显示“部位未明确”，不再在按钮旁或悬浮提示中显示长篇解释。每行仅有一个默认收起的“查看识别依据”，按原文去重，展示对应候选、来源、页码和分类原因。编辑及当前页面重绘保留展开状态，浏览器刷新后重新收起。原始全文保留，不改写旧订单数值、候选或确认状态。

新识别候选增加可选`evidence_status`（`direct`／`unverified`）和`evidence_reason`。自2026-10-20起，只有服务端原图核验可以产生`direct`：模型说明、坐标、置信度及旧记录自带的标记均不作为证明。备注中的推测、举例、参考及针对粗糙度的否定语句不自动生成原图候选；“Ra12.5不作为尺寸提取”等明确肯定粗糙度的说明仍可提取为待核实候选。

候选按数值及实际原图证据位置归并，`evidence_records`保留各来源原文、页码及坐标。相同证据的“端面／两端面”差异记录为部位待核对，不制造数值冲突；不同位置的独立标注继续保留，包括同值但不同页或部位的要求。未核实数值只在默认收起的依据中展示，不能快捷采用；可以查看后人工填写。没有可靠候选且正式参数为空时，可选择12.5／6.3项目参考，不添加及人工清空继续保留。

### 原图核验协议与旧订单

上传在参数融合前核验候选；旧订单读取时使用相同逻辑。v3分别核实数值和位置：“模型明确识别粗糙度＋原图PDF／本地OCR完整同值数字”，排除明确尺寸角色冲突后即可保留数值、等待人工确认；多处同值不会清空参数。OCR不必额外读出Ra或图形符号，不按固定数值放行。完整数字不能跨行、表格列或公差列拼接；普通尺寸、公差及其他字段有明确角色的数字不能借用。“▲：加工基准面”、模型置信度及说明不能单独证明数值存在。

同位指同页数字框中心位于模型框内，向外最多扩展一个OCR数字框短边；区域内多处同值不选点。模型框缺失时，可复核相同原图标识下的历史原图锚点／数字框（不使用气泡圆心）；没有历史依据时，仅同页唯一、无尺寸角色冲突的数字可自动恢复。多处同值保留“位置待核对”候选，允许采用数值后人工定位。新Qwen请求的粗糙度对象允许`occurrences: [{value, page, position, evidence, surface_location}]`，每处数字分别给归一化左上角框，无法确定时返回null，不新增请求。

v3增加无模型坐标的两端同值配对：声明为两端面或同值左右端面时，复用现有图形分区；仅唯一视图区内恰有两处独立同值数字、视图区像素长短轴比至少1.3、数字中心分别位于长轴首尾35%区域时生成两处12号气泡。多个视图或无法配对时只提示“数值已核实，位置待核对”，不抹去数值；一端定位成功则先显示一处气泡。结构化父字段及occurrences继承相同识别身份，保留父子原文，左右端同值归为两端面。旧误分类仅凭实际保存的结构化模型响应恢复；分析性备注、推测或推荐不会被升级。

可选元数据：`verification_version: "roughness_original_evidence/v3"`、`source_document_id`、`value_verified: boolean`、`verification_method: "explicit_label" | "model_position" | "historical_anchor" | "unique_number" | "end_pair" | "needs_location" | "unverified"`、`recognition_state: "located" | "needs_location" | "unverified" | "missing" | "failed"`。`independent_evidence: [{source: "pdf_text" | "ocr" | "local_ocr", page: number, position: {x,y,width,height}, text: string, location?: string}]`记录已定位证据，`numeric_evidence`保留核实数值的独立数字框；`expected_locations`记录明确端面声明需要的位置数。候选value_verified不等同于direct；参数value_verified对应当前值，不是人工确认状态。`recognition_position`保留原模型框。坐标均相对显示方向规范化页面；前端只读取服务端核验标记，不凭文字自行升级。旧记录允许缺少这些字段。原始识别快照、核验警告及升级审计不进入SW。

核验复用`annotation_ocr_v3.json`，粗糙度候选独立触发，不要求正式值或气泡已有位置。每页整页OCR完成后复用，失败可手动重试；单次补定位每页最多12个局部输入，旋转计入。完成区域不重复识别，历史缓存总数不限制新必要区域。`roughness_verification.json`按原图、v3、候选、有效历史锚点和OCR缓存修订复用；旧v1/v2拦截结果重判，失败普通打开不反复执行。不调用Qwen或新增云端服务。

未确认模型项没有独立数字证据时，正式值留空，疑似值折叠保存，不显示项目参考按钮；OCR失败显示失败原因。数值核实但位置不唯一时保留正式值、允许人工确认，并提示待定位。真正没有候选时才显示12.5／6.3／不添加。两端同值归为一个参数、两处12号气泡，多值或明确不同用途保持冲突。自动气泡只使用已定位direct证据，不依赖正式值是否为空、确认或冲突，位置可带`evidence_value`供提示；定位尚未完成不会阻止已确认有效数值输出SW。

旧v3标注仅刷新粗糙度自动位置；其他标注和最新人工位置保留，未变化的证据不增加标注修订。`POST /api/reviews/{id}/annotations/relocalize`仍返回完整标注文档，可选附带`roughness_update: {based_on_revision, parameter}`供前端通过保存队列同步草稿；并发编辑、修订或切换订单后不应用旧响应。人工填写、参考、人工确认及无法判断来源的旧值不静默修改；GET草稿经普通保存队列记录`roughness_evidence_verified`。旧技术要求不能未经核验填回。无新增业务接口或数据库迁移，冻结SW请求和重试保持原样。

## 端部状态自动要求

最终已确认且当前有效的端圈并紧状态和磨削状态，在 `solidworks_preview.extraProperties.技术要求` 第三项生成端部文字（前序缺项时连续编号）。仅并紧且磨平时使用“两端并紧并磨平，磨面角≥270°。”；不并紧且磨平时不自动追加角度。原图或用户明确填写的角度条件继续保留。

| 并紧状态 | 磨削状态 | 端部正文 |
| --- | --- | --- |
| 并紧 | 磨平 | 两端并紧并磨平，磨面角≥270°。 |
| 并紧 | 不磨平 | 两端并紧，不磨平。 |
| 不并紧 | 磨平 | 两端不并紧，端面磨平。 |
| 不并紧 | 不磨平 | 两端不并紧，不磨平。 |

复用 `end_coils_closed` / `end_grinding` 生图归一化值，兼容审图旧字段 `end_type`。缺项、待确认、失效、非法值或与当前快照不一致时不生成，沿用现有就绪规则。端部模板只存在于 SW 投影，不添加到审图技术要求列表、统计或内部原图要求数组；原有记录保留。完全等价的整句统一去重，不同角度、部位、附加条件及复合句保留。端部文字排在旋向和合并圈数之后，后续要求保持相对顺序并连续编号；已冻结历史请求和幂等重试保持原样。

## 并紧建模字段与最终版本

新建任务的 `modelParameters` 在并紧时包含七项，不并紧时省略“有效圈数n”后为六项，“是否并紧”排在“是否磨平”后，数字1表示两端并紧，0表示两端不并紧。复用已确认的 `end_coils_closed`，兼容 `end_type`，与端部文字同源。局部预览缺项为null，实际生图仍受原就绪检查约束。旧冻结请求及幂等重试不补写新键。

仅当最终建模属性“是否并紧”为数字0时，直接省略 `modelParameters.有效圈数n`，不传null或零占位；未知或未确认状态沿用原预览处理，不按不并紧推断。内部 `generation_parameters.spring_parameters.active_coils`、计算公式和生图确认要求继续保留。SW 技术要求将总圈数与有效圈数合并在第二项，不并紧时该行只输出总圈数；未知状态沿用现有预览缺项处理。此调整仅针对自动生成行，原图或人工填写的圈数要求按原有确认和等价去重规则保留，不同数值、作用范围和附加条件不合并。总圈数与有效圈数按首部合并规则输出。前后端预览、实际推送及新任务冻结使用同一投影；历史冻结请求即使仍含该键或原角度文字，也保持原样。

不并紧且磨平的建模字段示例：

```json
{
  "线径": 1.8,
  "中径": 25.2,
  "自由高度": 19,
  "圈数": 4,
  "是否磨平": 1,
  "是否并紧": 0
}
```

同一订单最多一个最终版本。`POST /api/generation-jobs/{generation_id}/approve` 遇到其他已选版本时返回409，`detail.code=final_generation_already_selected`，并返回 `current_final_generation_id`。先调用无请求体的 `POST /api/generation-jobs/{generation_id}/unapprove` 取消，再选择其他已完成版本；两种操作都返回现有 `generation_job` 响应并校验任务所有者。重复取消为幂等操作，不清除其他任务的选择。取消记录审计，不删除图纸、不改变任务完成状态、参数快照和审图修订。选定最终版本不阻断新任务或SW回调；新生图仍使用新的TaskId。

设计校核的计算依据和完整公式默认收起；同一页面会话保留用户手动开合，浏览器刷新后重新收起。
