# SolidWorks 命令格式

新建任务的 SW 请求与 `solidworks_preview` 使用相同模型投影。内部 `spring_generation_parameters/v2` 继续保留结构化材料、载荷点和原图技术要求；`solidworks_preview` 提供最终 SW 专用文本。

```json
{
  "TaskId": 1000000099,
  "models": [{
    "modelId": 1,
    "modelName": "订单2",
    "modelLabel": "压缩弹簧",
    "materialCode": null,
    "modelParameters": {
      "线径": 1.8,
      "中径": 25.2,
      "自由高度": 19,
      "圈数": 4,
      "有效圈数n": 2,
      "是否磨平": 1,
      "是否并紧": 1
    },
    "customProperties": {"旋向": "右旋"},
    "extraProperties": {
      "技术要求": "1.两端并紧磨平，每端磨270°。\n2.材料：SUS304。\n3.绕制方向：右旋。\n4.压并高度：Hb = 6.3 mm。\n5.当弹簧工作高度 H1 = 14.284 mm 时，对应工作载荷 F1 = 13.2 N。\n6.当弹簧工作高度 H2 = 12.284 mm 时，对应工作载荷 F2 = 18.9 N。\n7.总圈数：4 圈。\n8.有效圈数：2 圈。",
      "P'": 2.9314,
      "C": 14,
      "τ_b": 451.2669
    },
    "titleBlockProperties": {
      "材料": "SUS304",
      "重量": 0.00642403,
      "客户图号": "YD4765020178",
      "表面粗糙度": 12.5
    }
  }]
}
```

技术要求的八类完整正文等价规则与前端分组、重复新增和补回遗漏一致，详见[技术要求去重说明](technical-requirements.md)。例如“硬度 HRC45-50”和“HRC45-50”仅输出一次，保留各自原始记录；不同标尺、试验载荷、部位、标准版本和附加条件不合并，未支持工艺采用严格文本比较。原写法用于展示，比较副本中的单位、次数和区间规范化不会改写用户正文。

此例采用 SUS304、每端支承 1 圈、并紧磨平书页模型。Hb 已人工确认；没有图纸压并载荷 Fb，所以不把估算载荷写入技术要求。τ_b 仍使用有效估算结果。

- `P'` 使用 ASCII 单引号；三个计算键与“技术要求”并列，位于其后。值为 JSON 数字，四位小数，无单位字符串。合法零应力为 `0`，缺项、失效或不适用时省略对应键。
- 技术要求正文不重复标题，使用实际换行并连续编号。缺失条目跳过，其他已确认原图要求随后保留；模板句、结构化工艺要求及旧文本回退统一按完整条目去重，追加每条立即更新去重集合。不同原图位置的等价条目在新任务中只输出一次，原审图独立记录不删除；复合句及不同工程条件保留。
- 压并高度仅使用已确认、当前有效的输入或名义高度；上限参考不作为实际高度文字。唯一已确认的 Fb 与 Hb 高度一致时组合描述，不一致时分列并注明测试高度。没有 Fb 时只写 Hb。
- 工作点按原编号和顺序输出，保留百分比或绝对允差；支持 F3 等后续点。导出高度和力值转换为 mm、N，不支持的单位提示核对。
- `titleBlockProperties` 与 `extraProperties` 同级，按材料、重量、客户图号、表面粗糙度顺序输出。材料为已确认纯牌号，技术要求继续保留材料；重量为当前单件重量 Q，JSON 数字，单位 kg，最多八位小数；客户图号来自当前审图 `drawing_summary.drawing_no`，创建参数包时写入 `source.drawing_no` 并以字符串输出，仅去除首尾空白，保留前导零、字母、连字符及内部空白，不从文件名或任务编号补值；表面粗糙度为当前已确认、有效的 Ra 数字，单位固定 μm，不附单位文字。缺失键独立省略，重量缺失不影响客户图号，都缺失时发送空对象，不增加确认步骤或生图拦截。
- 粗糙度成功写入标题栏后，技术要求移除相同数值、单位、部位且无附加条件的独立粗糙度句，并连续编号。其它部位、不同数值、明确比较符以及复合工艺要求保留；不按关键词删除。原始参数、部位与识别证据继续保留。旧记录单位缺失沿用内部 μm 默认值，支持 µm、um 等价拼写，其它单位不直接当作 μm。
- 后端重新计算三个结果及重量，并在 `derived_parameters.solidworks_design_checks` 中冻结公式、输入、材料属性及版本。客户端缓存的 `design_checks` 不作为服务端依据。
- `solidworks_preview` 兼容旧 V2 记录缺少新增属性或客户图号；新任务冻结完整标题栏及图号快照，后续审图修改不影响该任务；历史任务的 `execution_options.solidworks_payload` 及幂等重试不改写、不补入客户图号。接口和数据库无需迁移，回调继续使用 `/api/solidworks/status`。

## 粗糙度缺值的可选参考

压缩弹簧的Ra确实缺失时，输入框下提供“采用 Ra 12.5／采用 Ra 6.3／不添加”三个快捷按钮，用户也可直接在输入框填写其他有效正数，不再单独提供“自定义”按钮。两个值均为两端面的项目参考，磨平、不磨平及端部状态未知时均可选择，不代表原图识别或统一标准规定。初次展示不修改参数、不默认确认、不写入SW；已有识别值、人工值、识别候选、冲突或失效数据不显示参考按钮，继续原有处理。

点击参考按钮填入对应的12.5或6.3、μm及两端面，来源包含`human_roughness_reference`，必须通过现有单项或批量确认后才输出标题栏JSON数字。直接输入改值后显示“人工填写”，撤销参考来源及旧确认快照。采用同一历史数值也不恢复原确认，不伪造原图文字、位置或气泡，不在技术要求编辑列表增加记录。采用审计记录实际`reference_value`，保存失败保留本地修改并提供重试。

“不添加”保持空值，并通过参数元数据`roughness_reference_dismissed=true`记住选择；保存重开收起提示，可点击“查看常规参考”重新选择。旧记录缺少标记时沿用缺值提示，已有人工清空默认收起；人工清空后不自动补回。选择及确认使用现有保存、审计和失败重试机制，无新增接口、数据库迁移或生图拦截。空值、未采用、未确认、失效和非法值继续省略`titleBlockProperties.表面粗糙度`；历史冻结请求及幂等重试保持原样。

验收（2026-10-18）：30组粗糙度阶段／端部组合通过前后端投影、保存重开和冻结请求检查；原有119组SW投影、参数确认及保存竞态回归通过。实际浏览器覆盖单项／批量确认、不添加与重新展开、自定义、失败重试、连续修改和切换订单；本地旧订单缺值结果离线验收未修改原文件。桌面及390px截图位于忽略目录`outputs/roughness-reference-qa/`。本机api、worker重建后健康检查及部署网页回归通过，未发起新的云端识别或真实外部生图任务。

### 粗糙度候选及原始依据精简

参数行只显示简短来源或核对状态；原图候选按钮为“Ra 数值 μm · 部位”，未知部位显示“部位未明确”，不再在按钮旁或悬浮提示中显示长篇解释。每行仅有一个默认收起的“查看识别依据”，按原文去重，展示对应候选、来源、页码和分类原因。编辑及当前页面重绘保留展开状态，浏览器刷新后重新收起。原始全文保留，不改写旧订单数值、候选或确认状态。

新识别候选增加可选`evidence_status`（`direct`／`unverified`）和`evidence_reason`。明确粗糙度文字或符号与数值一致时视为直接依据；备注中的推测、举例、参考及针对粗糙度的否定语句不自动生成原图候选。否定按对应语句判断，“Ra12.5不作为尺寸提取”仍保留；普通尺寸数字不当作Ra。长篇解释或依据不足的正向候选标为`unverified`，保留供人工选择，不自动填入正式参数。已有PDF/OCR的明确候选可提供直接证据，不追加云端或本地OCR调用。

候选按数值、单位、部位归并，`evidence_records`保留各来源原文、页码及坐标；左右端同值且依据明确时可合并为“两端面”，其他部位不因数值相同而合并。多个适用候选仍需人工选择及确认。旧记录缺少新元数据时只做展示分类，不重新融合或清除值；新字段不进入SW，接口和数据库表不变。

补充离线验证：`test_roughness_evidence.py`及共享`roughness_evidence.json`覆盖28组依据分类和反例；`test_surface_roughness_reference.py`扩展到40组，包括6.3参考值的待确认、确认、持久化及冻结投影。浏览器验证两个参考值、直接输入、原文折叠与去重、候选确认、保存重开及跨订单保护，截图为`reference-1440/390.png`和`compact-1440/390.png`。

## 端部状态自动要求

最终已确认且当前有效的端圈并紧状态和磨削状态，在 `solidworks_preview.extraProperties.技术要求` 首条生成端部文字。仅并紧且磨平时固定追加“每端磨270°”；不并紧且磨平时不自动追加角度。原图或用户明确填写的角度条件继续保留。

| 并紧状态 | 磨削状态 | 第一条正文 |
| --- | --- | --- |
| 并紧 | 磨平 | 两端并紧磨平，每端磨270°。 |
| 并紧 | 不磨平 | 两端并紧，不磨平。 |
| 不并紧 | 磨平 | 两端不并紧，端面磨平。 |
| 不并紧 | 不磨平 | 两端不并紧，不磨平。 |

复用 `end_coils_closed` / `end_grinding` 生图归一化值，兼容审图旧字段 `end_type`。缺项、待确认、失效、非法值或与当前快照不一致时不生成，沿用现有就绪规则。端部模板只存在于 SW 投影，不添加到审图技术要求列表、统计或内部原图要求数组；原有记录保留。完全等价的整句统一去重，不同角度、部位、附加条件及复合句保留。后续材料、旋向等模板保持顺序并连续编号；已冻结历史请求和幂等重试保持原样。

## 并紧建模字段与最终版本

新建任务的 `modelParameters` 在并紧时包含七项，不并紧时省略“有效圈数n”后为六项，“是否并紧”排在“是否磨平”后，数字1表示两端并紧，0表示两端不并紧。复用已确认的 `end_coils_closed`，兼容 `end_type`，与首条端部文字同源。局部预览缺项为null，实际生图仍受原就绪检查约束。旧冻结请求及幂等重试不补写新键。

仅当最终建模属性“是否并紧”为数字0时，直接省略 `modelParameters.有效圈数n`，不传null或零占位；未知或未确认状态沿用原预览处理，不按不并紧推断。内部 `generation_parameters.spring_parameters.active_coils`、计算公式和生图确认要求继续保留。SW 技术要求在不并紧时省略自动圈数行，并紧时自动输出“有效圈数：对应值 圈。”，替代旧名称“工作圈数”；未知状态沿用现有预览缺项处理。此调整仅针对自动生成行，原图或人工填写的圈数要求按原有确认和等价去重规则保留，不同数值、作用范围和附加条件不合并。总圈数文字及其输出顺序不变。前后端预览、实际推送及新任务冻结使用同一投影；历史冻结请求即使仍含该键或原角度文字，也保持原样。

不并紧且磨平的建模字段示例：

```json
{
  "线径": 1.8,
  "中径": 25.2,
  "自由高度": 19,
  "圈数": 4,
  "是否磨平": 1,
  "是否并紧": 0
}
```

同一订单最多一个最终版本。`POST /api/generation-jobs/{generation_id}/approve` 遇到其他已选版本时返回409，`detail.code=final_generation_already_selected`，并返回 `current_final_generation_id`。先调用无请求体的 `POST /api/generation-jobs/{generation_id}/unapprove` 取消，再选择其他已完成版本；两种操作都返回现有 `generation_job` 响应并校验任务所有者。重复取消为幂等操作，不清除其他任务的选择。取消记录审计，不删除图纸、不改变任务完成状态、参数快照和审图修订。选定最终版本不阻断新任务或SW回调；新生图仍使用新的TaskId。

设计校核的计算依据和完整公式默认收起；同一页面会话保留用户手动开合，浏览器刷新后重新收起。

### 本次验收记录（2026-10-15）

最终版本交互沿用现有工作台样式。已检查桌面和窄面板：当前最终版本显示取消按钮，其他选择按钮禁用并使用浅色状态；接口409后重新读取服务端结果，失败及跨订单晚到响应不会错误解锁。计算依据首次收起，用户手动开合在局部刷新中保留。

验证覆盖99组Python/JavaScript SW投影、版本设置/取消及SW进度完成回调、保存和参数确认竞态。独立PostgreSQL临时schema中并发设置两个版本只成功一个，并发重复取消仅记录一次审计；测试结束清理临时schema，原订单、参数快照及审图修订未修改。浏览器交互及截图保存在忽略目录 `outputs/final-selection-qa/` 和 `outputs/design-check-compact-qa/`。这些验收使用本地测试数据和模拟SW，不提交真实外部生图任务。本次UI范围验收结论：可交付；现有界面外观及其他区域不重新设计。
