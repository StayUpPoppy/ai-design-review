# 技术要求逐条保留、历史补回与 SW 输出

技术要求以独立原图条目保存，分类仅用于标签，不再让相同类型的不同内容竞争一个参数字段。普通尺寸、材料、圈数、旋向和载荷继续走现有参数流程；粗糙度继续使用独立参数行。

每条要求具有 `requirement_id`、`original_number`（可重复或为空）、`source_order`、`recognition_key`、`recognized_content`，并保留原文、译文、位置和证据。同一原图条目的重复识别可以合并；不同位置或顺序的条目不因类型或译文相似而合并。初次识别沿用原有置信度、表面处理及翻译确认规则；历史补回条目一律待确认。

## 历史补回

`POST /api/reviews/{job_id}/technical-requirements/recover-preview` 接收 `expected_revision`。接口检查订单归属和修订号，优先读取 `qwen_vision_raw.json` 的原始列表，必要时读取 `candidates.json`；不调用 Qwen/RAG，不修改文件或数据库。

返回 `job_id`、`based_on_revision`、`source`、`items`、`order_hints` 和提示。每个候选包含 `requirement`、`status`（`available` 或 `possible_existing`）和原因。只有唯一匹配的旧条目提供顺序提示，不覆盖正文或确认状态。没有原始记录时提示重新识别或人工补充，不能保证恢复模型本身没有识别出的内容。

前端“补回遗漏技术要求”提供预览与勾选，可能已存在的条目默认不选。确认选择后添加为待确认，并通过现有串行保存机制记录 `technical_requirement_recovered`。保存失败保留本地结果，重试只保存、不重复补入。编辑或切换订单后返回的旧预览不得直接应用。用户删除的条目根据审计记录排除；历史记录不足时保守提示可能已存在。

## 输出约定

新建任务的后端预览、SW 请求和前端本地预览使用统一的完整条目等价规则：同一模型、相同作用范围及全部工程条件相等时只输出一次，即使原图位于不同页或区域。每追加一条立即更新去重集合，最后连续编号，开头类别标签仅输出一次。不同温度、时间、允差、部位、标准、否定或检验条件的要求保留；复合句不按部分内容重复删除。

比较只规范空格、全半角标点、末尾句号及 ℃/°C、µm/μm 的表示；类别标签使用固定白名单，只移除开头明确标签，不删除“热处理后检查”等正文。数字、正负号、±、不等号和小数保留，不使用模糊相似度或额外模型调用。Python `technical_requirements.py` 与浏览器 `technical-requirement-equivalence.js` 通过共享样例核对。

已确认的等价条目分别保留 ID、证据、确认与审计记录，重复本身不阻止确认或生图。未确认的独立记录继续要求人工确认，不能继承其他条目的确认。未确认或真正翻译失败的内容不输出；翻译工程差异沿用警告及人工确认机制。

原图同一要求被参数通道及逐条技术要求通道重复提取时，优先保留逐条记录，其他通道存入 `recognition_aliases`。每个别名保留 recognition_key、original_content、recognized_content、page、position、source 和 evidence。页码、正文和位置证据需一致；多处同文不能明确归属时不合并。不以重复序号判断同一原图条目，原始候选文件不改写。

补回遗漏同时检查主记录及别名，人工编辑或删除后不会再次补入别名；旧记录缺少别名时视为空列表。明确作用范围可通过可选 `application_scope` 保存和冻结，在输出中注明；更多范围与工程条件仍保留在原文中。

历史审图数据不批量清理。已冻结请求及幂等重试保持原样；修改后的规则用于新建任务。内部结构化技术要求保留，最终去重只生成输出副本，不调整计算、材料或载荷字段。

## 前端显示去重与统一操作

编辑列表使用同一等价键生成展示副本，每组只有一个正文编辑框、类型选择和确认按钮。选择阅读顺序中第一条有效已确认记录作为代表，没有可输出记录时选择第一条；按代表的原始位置排序，保证已确认用户要求的正文与顺序和 SW 输出一致（参数生成的模板文字及全局编号另行处理）。空条目不互相隐藏。页面顶部按去重项统计，同时显示原始记录数和可输出条数；部分确认不视为整项已确认，也不继承确认。

每项注明对应原始记录数量，默认收起的“查看识别来源”保留各条原文、页码、证据、别名及确认状态。显示去重不写回数据。历史记录缺少原文时，第一次人工编辑保留原先正文供追溯。

用户一次编辑会同步该项对应的全部记录，并分别撤销确认、记录审计；一次确认仅在全部记录可以确认时执行，分别保存确认快照。翻译阻断和保存失败仍显示在正文下方，不能通过代表记录绕过。整项删除包含对应全部记录，一次撤销恢复原顺序、内容和确认信息。新增同文要求只提示并定位现有项。

编辑开始固定记录 ID，输入期间不重组；提交后重新计算展示项，保留焦点、光标和来源展开状态。编辑后变为同文的条目自动只显示一次，但不自动确认。各记录的变更事件通过现有修订号及保存队列一起提交，失败重试不重复新增，旧响应不能覆盖新修改；保存重开重新生成展示副本，无需新接口或数据库迁移。

原生失焦提交会等待当前点击结束后刷新，避免替换按钮或保存提示引起布局移动而吞掉确认点击。尚未发出的编辑与确认可以进入同一保存批次；正在保存时等待保存完成并核对正文快照，期间有新的编辑则不自动确认新内容。

当前审图导出时，正文中明确的原图列表编号只在输出副本中移除，再生成连续输出编号；不修改原文、输入框或原图序号标签。历史条目缺少序号元数据时，仅识别清晰的整数列表前缀，`12.5 mm` 等尺寸数字保持不变。

## 验证范围

专项测试覆盖同类型多条、多页和重复编号、历史编辑／删除保护、预览修订冲突、失败重试及过期响应。桌面和 390px 窄栏的实际浏览器检查覆盖预览勾选、独立确认、保存后重新打开、按钮换行和无横向溢出。前端沿用现有浅色工程工作台布局；该局部扩展按 impeccable 的健壮性规范检查，没有引入新的视觉体系或静态图片资源。

部署重建并重新创建 api、worker，更新挂载的前端目录和缓存版本后强制刷新；无需数据库迁移。真实 SW 的长备注换行和图框容量需要联调核对，本项目不能保证外部模板不会截断，不得为适应版面静默删除条目。
