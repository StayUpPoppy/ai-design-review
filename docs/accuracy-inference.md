# 公差反推整体报价精度

待处理与参数确认页共用执行标准、通用精度选择和标准化操作。待处理页将设置放在“生成并应用标准化方案”步骤内，参数页将“标准化设置”放在参数合理性与建议上方。执行标准优先采用人工选择，其次采用图纸标准和系统推荐。标准、等级不占尺寸表行，不参与尺寸批量确认；人工改选即保存，系统推断保留原有来源及自动模式。首次识别明确写有通用等级时保留图纸等级；否则按独立公差逐项匹配1／2／3级，整体取最严格的一项。不自动应用公差。

## 计算依据

冷卷GB/T 1239.2-2009按1／2／3级反推受控内外径、自由高度、载荷和刚度。内外径公差以中径D乘表内系数，计算前统一单位，结果按参数原单位返回。热卷GB/T 23934-2015按T／1／2／3级反推直径、自由高度和负荷。热卷逐项检查公式输入，适用范围仅保留作依据，节距和有效圈数缺失不阻止已有输入项目计算。冷卷查表范围继续保留，表外提示手填公差。后端复用现有分段、系数、最小限值和四位小数计算函数；前端规则副本通过共享样例及规则表全量对照验证。精度判定不调用Qwen或RAGFlow。

尺寸与上下偏差统一单位；百分比载荷公差按对应力值换算。完整偏差区间落在某级允许区间内，才满足该级，冷卷按1→2→3、热卷按T→1→2→3依次判断。单边公差必须明确另一侧为0，缺失不补零；不对称公差不按公差带宽度折半。严于一级仍匹配1级，内部记录更严要求。缺项、非法值、超三级及标准不适用均不伪造匹配；有效项目不足时记录完整性，无有效结果沿用公司默认2级待确认。

分项反推只保存在内部，不写入四个专项精度字段；自动模式保留图纸专项等级优先。人工选择通用等级后，各项建议统一采用所选等级，原图专项等级保留作来源并展示差异。多个有效项目为1、2、3级时，报价参考取1级。

## 选择、来源与保存

审图JSON可选增加 `accuracy_inference`，包含 `selection_mode`（auto／manual／drawing／legacy）、`rules_version`、`input_snapshot`、`observed_inputs`、`results`、`inferred_grade`、`complete`、`calculation_fingerprint`。现有 `accuracy_grade.value` 仍是最终采用值。

自动模式下，独立尺寸或公差变化后重新判断；等级改变撤销旧等级确认，等级不变保留确认。下拉框改选即保存并进入人工模式，AI指令改选等级使用同一优先级。之后分析只更新内部参考，保存、刷新和重开不覆盖人工等级。

原图与直接人工输入的结构化值保存为独立快照。参数可选 `tolerance_source`、`accuracy_value_source` 分别记录公差和数值来源；标准化、公式和建议应用写入系统来源，不覆盖独立快照。人工直接编辑对应部分才更新独立输入。仅确认系统生成值不改变来源；原图原文与现有审计继续保留。

沿用修订号、审计、保存失败重试及冲突合并。标准化与AI回复绑定当前订单、服务地址及导航序号，晚到回复不替换其他订单。旧订单缺少元数据或规则版本升级时保留原等级及确认状态，仅补内部分析。旧建议标记过期，显式重新标准化后使用当前规则。无需新业务接口或数据库迁移，元数据不进入SW请求，历史冻结任务及重试不变。

本次有后端修改，部署执行 `docker compose up -d --build api worker`，检查 `/api/health` 后Ctrl+F5刷新。新订单验证自动选级，修改等级并应用公差后保存重开，确认人工选择保持。

## 执行标准与建议应用

标准化按钮从保存等待开始显示加载图标，两个页面共享状态，期间禁止重复提交及改选。结果按目标字段统计“已生成 X 项，Y 项未能生成”，参考上限和执行标准记录不计入建议数量。缺项与查表越界作为独立诊断展示在汇总和载荷公差旁，不参与应用。冷卷按载荷点返回缺有效圈数等结果，前端兼容历史 `load_points` 集合诊断；热卷缺刚度时关联已有刚度公式缺项。参数变化后旧原因显示待更新，重新计算后清除或更新。原公差保留，沿用单项、批量应用和撤销。

`standard_selection.selected_standard`是当前执行标准，`selection_source=human_selected`表示人工选择，`metadata.drawing_standard`保留原图标准。标准与精度改选立即进入现有保存队列，两处控件同步。热卷T级切到冷卷时清空当前等级，待选1／2／3级。保存失败显示重试入口，保存成功后可重新标准化。

重新标准化只生成建议。单项及批量应用按当前规则版本和输入指纹核对新鲜度，批量应用包括已有手填公差，应用前显示项数，应用后记录审计并支持原有撤销。原始独立公差快照继续用于反推，系统应用结果排除在独立证据之外。

`standardization_context`保存规则版本与输入指纹，改变标准、等级或计算输入后，旧建议及对话批次标为过期。服务端重新核验保存与应用，晚到结果继续受订单归属、输入版本和审图修订校验保护。

本地验收包含`test_execution_standards.py`、`test_execution_standards_ui.mjs`及`test_accuracy_inference_browser.mjs`。

待处理页的标准化按钮位于“查看并处理建议”左侧，三项操作同组、同字号和高度，窄屏按顺序换行；参数页按钮保留在设置区标题旁。诊断通过现有刚度计算器解析真实缺项：结果元数据的 missing_fields 保存直接缺项（如刚度），可选 root_missing_fields 保存公式所需输入（如有效圈数）。合理性问题的 fields 对应实际定位输入，affected_fields 保留所有受影响的载荷目标。相同规则和缺项的 F1/F2 问题合并，卡片显示具体处理方式及“补充有效圈数”等定位按钮；已有有效人工刚度不要求补充有效圈数。旧记录按当前参数读取公式诊断，输入变化后不展示旧缺项。诊断解析不写入公式值或公差。
