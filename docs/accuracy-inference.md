# 公差反推整体报价精度

通用精度下拉框同时服务报价参考与现有标准化流程，界面不增加另一组精度、对照提示或按钮。首次识别明确写有通用等级时保留图纸等级；否则按独立公差逐项匹配1／2／3级，整体取最严格的一项。自动结果仍走现有确认流程，不自动应用公差。

## 计算依据

仅支持已接入GB/T 1239.2-2009规则的受控内径／外径、自由高度、载荷和刚度。后端复用现有分段、系数、最小限值和四位小数计算函数；前端规则副本通过共享样例及规则表全量对照验证。精度判定不调用Qwen或RAGFlow。

尺寸与上下偏差统一单位；百分比载荷公差按对应力值换算。完整偏差区间落在某级允许区间内，才满足该级，按1→2→3依次判断。单边公差必须明确另一侧为0，缺失不补零；不对称公差不按公差带宽度折半。严于一级仍匹配1级，内部记录更严要求。缺项、非法值、超三级及标准不适用均不伪造匹配；有效项目不足时记录完整性，无有效结果沿用公司默认2级待确认。

分项反推只保存在内部，不写入四个专项精度字段；已有明确专项等级仍按原逻辑优先。多个有效项目为1、2、3级时，报价参考取1级。

## 选择、来源与保存

审图JSON可选增加 `accuracy_inference`，包含 `selection_mode`（auto／manual／drawing／legacy）、`rules_version`、`input_snapshot`、`observed_inputs`、`results`、`inferred_grade`、`complete`、`calculation_fingerprint`。现有 `accuracy_grade.value` 仍是最终采用值。

自动模式下，独立尺寸或公差变化后重新判断；等级改变撤销旧等级确认，等级不变保留确认。下拉框生成方案或AI指令明确改选等级后进入人工模式，之后分析只更新内部参考，保存、刷新和重开不覆盖人工等级。

原图与直接人工输入的结构化值保存为独立快照。参数可选 `tolerance_source`、`accuracy_value_source` 分别记录公差和数值来源；标准化、公式和建议应用写入系统来源，不覆盖独立快照。人工直接编辑对应部分才更新独立输入。仅确认系统生成值不改变来源；原图原文与现有审计继续保留。

沿用修订号、审计、保存失败重试及冲突合并。标准化与AI回复绑定当前订单、服务地址及导航序号，晚到回复不替换其他订单。旧订单缺少元数据时保留原等级及确认状态，仅补内部分析。无需新业务接口或数据库迁移，元数据不进入SW请求，历史冻结任务及重试不变。

## 离线验证与部署

运行 `scripts/test_accuracy_inference.py`、`scripts/test_accuracy_inference_ui.mjs`、`scripts/test_accuracy_inference_api.py` 和 `scripts/test_accuracy_inference_browser.mjs`，覆盖共享边界、原图等级优先、混合取严、单位、载荷分段、人工锁定、系统来源防循环、保存重开、失败重试、冲突、焦点及窄面板。API测试使用临时SQLite与本地规则，浏览器API全部模拟，不调用云端识别或生产SW。

本次有后端修改，部署执行 `docker compose up -d --build api worker`，检查 `/api/health` 后Ctrl+F5刷新。新订单验证自动选级，修改等级并应用公差后保存重开，确认人工选择保持。
